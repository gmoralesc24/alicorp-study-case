Centro de Control: ML para Potencial Incremental

Caso de Estudio: Estimador de Potencial Incremental

El Problema y Objetivo

Actualmente, identificar el potencial de crecimiento de los clientes (bodegas y mercados) se basa en métricas reactivas como el volumen del ticket de la última compra. Esto no permite priorizar adecuadamente a los clientes que, aunque compran poco hoy, tienen una alta probabilidad de incrementar sus ventas futuras.

El objetivo: Desarrollar un modelo predictivo de Machine Learning que estime la probabilidad de que un cliente posea un verdadero potencial incremental, logrando así una segmentación proactiva para dirigir iniciativas comerciales (ej. Cliente Perfecto, mercaderismo, líneas de crédito) donde el retorno de inversión sea mayor.

Metodología Aplicada

  • Ingeniería de Características (RFM): Transformación de 392 mil registros transaccionales en variables de Recencia, Frecuencia y Monetario por cliente.
  • Tratamiento de Datos: Uso de técnicas avanzadas como SMOTE para balancear la variable objetivo altamente desbalanceada.
  • Modelado: Construcción y evaluación de algoritmos basados en árboles (Random Forest y Gradient Boosting) maximizando la curva ROC-AUC.
  • Despliegue Web (Serverless): Conversión del modelo predictivo para que se ejecute en vivo usando WebAssembly (PyScript) en el navegador del usuario final.

Nota Técnica: Calibración y Ajuste del Modelo

Durante la auditoría de despliegue, se optimizó el dataset sintético y el motor de inferencia para garantizar resultados fiables en la web:

  • Reingeniería del Target (Lógica de Negocio): Se reemplazó el ruido aleatorio del dataset original inyectando una regla matemática estricta basada en el comportamiento RFM. Esto dotó al Random Forest de un patrón real que incrementó el Test AUC a ~0.87.
  • Undersampling en PyScript: Dado que WebAssembly no soporta SMOTE, el simulador ejecuta un balanceo dinámico de datos (50/50) usando Pandas justo antes del entrenamiento en el navegador.
  • Imputación de Media (Mean Imputation): Las 16 variables que el usuario no ingresa manualmente en el simulador no se inicializan en cero, sino que el script calcula e inyecta dinámicamente sus promedios históricos para evitar anomalías en el árbol de decisiones.

ℹ️ Ver variables preestablecidas (Imputación de Media Histórica)

El modelo predictivo requiere 21 variables para operar. Para simplificar esta demostración interactiva, se evalúan 5 variables clave manualmente. Las 16 variables restantes se imputan dinámicamente utilizando la Media Histórica del Dataset, asegurando que el motor de inferencia reciba un perfil realista y previniendo anomalías matemáticas:

  • Iniciativas Comerciales: Probabilidad histórica de participación en el programa Cliente Perfecto y recepción de Impulsos de Marketing.
  • Comportamiento de Compra: Categorías Únicas compradas (fijado en 3) y Ticket Promedio (calculado automáticamente según frecuencia y monto).
  • Descuentos y Promociones: Monto Total de Descuento Acumulado y Tasa Promedio de Descuento de la cartera general.
  • Demografía y Geografía: Variables de distribución territorial (Territorios T1 al T6) y tipología del negocio (Segmentos S1 al S6), asumiendo el centroide poblacional del dataset.
